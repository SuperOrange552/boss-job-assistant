# BOSS 软件测试岗位助手

这是一个可以通过 Chrome“加载已解压的扩展程序”安装的 Manifest V3 扩展。你先自行选好 BOSS 求职列表并停留在“左侧岗位列表＋右侧岗位详情”页面，然后在右下角设置本轮最多成功投递数并点击“开始”。插件会从当前岗位开始，按当前页面的左侧顺序逐条向下识别、调用智谱或 DeepSeek 生成招呼语，并在后台临时标签页中发送文字和可选的简历图片。插件不主动导航原职位列表；网站或其他工具仍可能改变页面，不能保证页面永不跳转。

## 0.4.19：同步通用版 0.2.6 的异常页面处理，招呼语改为按职位描述 + 个人总结、真人语气

### 沟通点击 / 异常页面（沿用通用版 0.2.6 的判断流程）

- **“继续沟通”中间页**：点击“立即沟通”后仍停在同一岗位详情、没有聊天输入框，但按钮变成“继续沟通”时，接着点一次“继续沟通”。同一任务“立即沟通”“继续沟通”各最多一次，由后台原子登记，页面重载也不会重复点击。
- **同岗位详情中间标签**：BOSS 先打开同一岗位的详情中间页时，沿用原任务、话术和简历图片配置继续处理，结束后一并关闭临时标签。
- **微信订阅 / 二维码弹层**：只在点击沟通之后、等待聊天输入框时判断；弹层同时含“订阅”和“消息”，或明确提示二维码/扫码时，只点弹层内部的关闭按钮，然后继续当前岗位。验证码 / 安全验证类弹层不在此列，仍按平台限制停止。
- **按钮带聊天地址**：沟通按钮本身提供站内聊天地址时，直接让当前临时标签进入该地址。
- **发送按钮误选修复**：只认真实按钮或明确的发送控件，不再把文字恰好是“发送”的外层容器当成按钮；草稿和按钮连续两次就绪才点击。
- **准备草稿与请求发送分两阶段**：草稿填好但未点发送不算已沟通；点击前在后台登记唯一发送请求，之后页面怎么重载都不自动重发。输入框里已经是本条话术时直接沿用，不会覆盖别的草稿。
- **点击后按钮变成“继续沟通”却始终没有聊天框**：可能是 BOSS 自动默认打招呼已发出，记为“发送结果待核对”，不重发，继续下一条。
- 等待上限与 0.2.6 默认值一致：岗位详情 30 秒、聊天页/输入框 60 秒、发送按钮就绪 15 秒、文字发送确认 15 秒；页面提前就绪会立即继续。0.4.x 原有的聊天会话身份核对、HR 活跃筛选、大中厂/外包预筛、失败继续下一条全部保留。

### AI 写作要求

- 设置页“招呼语规则”改名为“AI 写作要求”，默认内容改为：先读职位描述，从岗位职责和任职要求里挑 1～2 个最核心的点切入，再结合个人总结有针对性地讲自己做过的相关事情和细节，用真人聊天的语气写，3～4 句、80～150 字。
- 去掉了对模型的真实性约束（“只选真实经验”“只表达已经具备的优势”“不得推断离家近”等），允许模型围绕个人总结自然展开细节。
- 不再强制固定开头“X老师您好，看贵公司在招聘XX岗位，”；只统一称呼为“X老师您好，”，后面由模型按职位描述自然开场。公司全称仍替换为“贵公司”（猎头/多主体为“您这边”）。
- 仍保留两条强制保护：不自曝短板；不罗列技能清单、最多 2 个工具名。
- 已保存的旧默认规则会自动换成新版默认；你自己额外补充的行会保留，附在新版规则后面。

## 当前规则

- 只把岗位位置标识为“上海”或“上海·区·商圈”的岗位纳入投递范围。
- 常规软件测试、功能测试、接口测试、自动化测试、性能测试、游戏软件测试、App/Web/H5测试等方向可以推荐；游戏测试描述里仅出现“手机硬件配置/软硬件兼容”这类泛词时不会误判为硬件岗。
- 硬件、嵌入式、车载、整车、汽车、光学设备等方向进入“当前暂缓”，不会调用模型或发送。
- 已沟通未回复的岗位不会永久排除。第一次之后默认至少间隔 4 小时才允许第二次，第三次从上海时间次日开始允许；三次以后停止继续发送。设置页可调整二次沟通间隔。
- 同公司其他岗位默认 24 小时内不会重复发送，设置页可调整；匿名或未识别公司不使用公司级防重。
- 已成功沟通过的岗位会在左侧岗位卡片标记“本岗位已沟通 N 次”，同公司的其他岗位标记“同公司已有沟通”。记录保存在扩展本地，重新开始一轮也会继续生效。
- 每成功发送 1 条消息后随机休息 1～3 秒；每累计成功发送 10 条，再额外休息 10～30 秒。
- 每次点击“开始”都会创建一个新运行，并使用你当时填写的“本轮最多成功投递数”；达到该数立即停止。之后可以重新填写数量并再次开始。
- 开始时会同时锁定 BOSS 顶部当前求职方向（例如“测试开发（上海）”）。自动发送不主动让原职位列表跳到消息页；每条正常发送完成后关闭后台临时标签页，原列表从下一个未处理岗位继续。原列表本身重载/离开则暂停，不再自动恢复方向。
- 可以在设置页选择并保存一张 JPG、PNG 或 WebP 简历图片（最大 8 MB）。开启后，每条招呼语取得成功证据后才继续发送图片；图片发送也取得明确聊天记录证据后，该条才完整完成。
- 每日成功发送上限默认为 500，达到 BOSS 实际平台上限或出现异常提示时应立即停止。
- 自动模式在开始时统一确认一次，本轮不再逐条确认。单条手动模式仍可以只生成、复制或二次确认后发送。

模型话术必须以当前岗位的职责和任职要求为主，个人总结只是用来挑选1～2项能直接回应该岗位的经验，不会再把整段简历压缩成技术名词清单。每条最多提及2个岗位真正需要的工具或技术栈，并用2～3个自然句子表达。模型返回后，扩展还会统一把开头整理成“X老师您好，看贵公司在招聘X岗位，……”，避免出现“老师好，看到XX公司在招……”这种生硬写法。

话术保留不自曝短板、不罗列菜单式技术清单的约束。第一次不合格会要求模型重写；第二次仍不合格时，不再把推荐岗位直接丢弃：仅在个人总结中确实有对应经历时，用当前JD与个人总结交集中的一项经历生成简短备用话术。无可靠匹配内容时记为“话术问题”，不计作岗位不符合。不会仅根据上海地点推断公司离家近。

## 2. 在扩展设置页填写接口

### 智谱 AI（默认）

```text
提供商：智谱 AI
API Base URL：https://open.bigmodel.cn/api/paas/v4
模型名称：glm-4.7-flash
API Key：填写你的智谱开放平台 API Key
```

这里应使用智谱普通开放平台 API Key，不要填写只面向编程工具的 Coding Plan 专属端点。如果账户使用其他模型，可以直接修改“模型名称”。

### DeepSeek

```text
提供商：DeepSeek
API Base URL：https://api.deepseek.com
模型名称：deepseek-v4-flash
API Key：填写你的 DeepSeek API Key
```

切换提供商时，设置页会自动填入相应的默认 Base URL 和模型名称。下面两种智谱地址都可以填写，插件会自动规范化，避免把 `/chat/completions` 重复拼接两次：

```text
https://open.bigmodel.cn/api/paas/v4
https://open.bigmodel.cn/api/paas/v4/chat/completions
```

点击“保存并测试接口”会先保存设置，然后发起一次小型模型请求验证 API Key、接口和模型是否可用；这次测试可能产生少量模型用量。

API Key 输入框默认以密码形式隐藏，可以点击“显示”临时查看，也可以点击“清空”从扩展存储中删除。

## 3. 使用

1. 由你自己打开并选择好 BOSS 求职列表，不要让插件切换搜索方向；页面应同时显示左侧岗位卡片和右侧完整职位描述。
2. 在右下角助手中填写“本轮最多成功投递数”，点击“开始”。确认框会明确显示本轮锁定的顶部求职方向；如果显示的不是你刚刚选择的方向，请取消，不要启动。
3. 如需附带图片简历，先在扩展设置页的“简历图片”区域选择图片，点击“保存所选图片”，确认开关已经勾选。
4. 插件从当前左侧岗位开始逐条向下：读取右侧“上海”地点、岗位标题、职责、要求、招聘者和活跃信息。
5. 猎头/外包及硬件、嵌入式、车载、整车、汽车和光学设备岗位在本地跳过；普通软件测试先完成本地公司、岗位、HR与防重检查，再调用模型仅生成招呼语。
6. 插件保存待发送任务并打开一个不抢焦点的后台临时标签页。临时页确认岗位和沟通按钮一致后进入聊天；如果 BOSS 把聊天打开到新标签页，新页会继承同一投递任务并继续发送。原列表页保持当前位置和原有顺序。
7. 招呼语完整写入输入框、目标相符且找到发送按钮后才点击；输入框清空且聊天记录出现本次文字后，才继续选择并发送简历图片。
8. 图片开启时，只使用聊天区域中唯一识别出的图片上传控件；聊天记录出现新图片并且图片确认窗口消失后，才将图片标记为发送成功。临时页随后关闭。
9. 每条成功后，原列表页等待 1～3 秒；第 10、20、30……条叠加 10～30 秒批次休息。主列表标签页隐藏/窗口最小化时暂停读取和点击，恢复可见后再继续。临时发送页仍可后台执行。
10. 单条目标不一致、加载/发送失败则记日志并跳过。达到本轮成功上限、列表到底、用户停止时结束；平台验证码/账号限制或来源列表离开等全局问题才暂停。

更新到0.4.5后，旧版遗留的运行中任务会停止，等待你亲自开始。旧的2～8秒等待配置自动迁移到1～3秒，其余设置和沟通记录保持不变。0.4.5修复同名岗位选择、隐藏CSS污染和话术误拦截；加入详情稳定校验与运行诊断日志。扩展重新加载后需要刷新一次已经打开的BOSS标签页。此版本已做本地模拟验证，真实BOSS页面仍需小范围验证，不代表已经实测投递。

## 发送保护

- 单条直接发送默认不开启；自动投放必须由用户在当前职位列表页点击“开始”并确认本轮上限。
- 找不到唯一的沟通按钮、输入框或发送按钮时，只跳过本条；不使用固定屏幕坐标盲点。
- 找不到启动时锁定的顶部求职方向，或方向切换后列表没有稳定加载时停止；不会退回“推荐”继续投递。
- 点击发送后，只有同时检测到输入框清空和页面出现本次消息才记录为成功；状态不明确时本条不计数、记录“待核对”且不自动重发，继续下一条。
- 发送简历图片前确认图片已保存且聊天区域存在唯一可信的图片输入控件；否则记录本条未发送并跳过。
- 若文字已经取得成功证据但图片失败，保留文字防重并记录图片失败，继续下一条，运行后可查看日志并人工核对图片。
- 出现验证码、账号异常、平台限制或其他风险提示时，不应继续操作。
- 插件不会绕过验证码或安全验证，也不能保证 BOSS 不触发风控。BOSS 页面结构更新后，需要重新做一次现场验证。

## 数据边界

扩展本地保存：

- 个人总结。
- 模型提供商、API Base URL、模型名称和招呼语规则。
- 你填写的 API Key。
- 岗位 ID、公司、岗位名称和岗位 URL。
- 已成功发送的时间、轮次和消息文本。
- 今日成功发送数量和休息结束时间。
- 当前自动投放运行的上限、已识别/跳过/成功数量，以及跨页面恢复所需的待发送任务。
- 可选的简历图片副本、文件名、类型和大小；它只存在于当前 Chrome 扩展的本地存储，不会放进扩展目录或压缩包。

调用智谱或 DeepSeek 时会发送：

- 当前岗位名称、公司、上海位置、岗位标签和职位描述。
- 招聘者页面显示名称与活跃信息。
- 个人总结。
- 当前是第几次沟通。

API Key 保存在 `chrome.storage.local` 中，只允许扩展设置页读取完整值。BOSS 页面中的内容脚本、扩展弹窗、岗位记录和控制台日志都不会获得或输出完整 Key。这个存储是 Chrome 扩展的持久化本地存储，但不是加密密码保险箱；不要在公共电脑或多人共用的 Chrome 配置中保存。

简历图片同样保存在 `chrome.storage.local`，只会在你开启自动附带图片后交给当前临时 BOSS 投递页上传，不会包含在发送给智谱或 DeepSeek 的模型请求中。浏览器出于安全原因不能长期持有并自动读取普通本地文件路径，因此需要在设置页选择并保存图片副本。
