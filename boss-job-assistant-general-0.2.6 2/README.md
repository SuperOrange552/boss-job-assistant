# BOSS 通用岗位助手 0.2.6

这是单独生成的通用 Chrome 扩展。它不包含制作者的个人简历、API Key、简历图片、沟通历史、目标城市、目标岗位、屏蔽公司名单或行业偏好。所有业务筛选默认留空，由每一位使用者自己填写。

> 重要边界：本包已通过本地语法、规则和模拟后台测试，但没有在此构建过程中连接或控制真实 Chrome，也没有向真实招聘者发送消息。BOSS 页面改版后，DOM 读取和发送流程仍需由使用者在自己的账号上小范围核对。验证码、平台限制、身份不一致和发送结果未知不会被绕过。

## 安装

1. 解压后保留整个 `boss-job-assistant-general-0.2.6` 文件夹。
2. Chrome 打开 `chrome://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择上述文件夹。
4. 打开扩展详情中的“扩展程序选项”，先填写并保存设置。
5. 打开 BOSS 岗位列表，由本人选好求职方向和页面列表，再在面板中设置本轮上限并开始。

> **发送前必须检查：使用这个软件需要关掉自动默认打招呼设置（BOSS 内的设置），不然消息发送不过去！！！**

不要把本目录覆盖到个人定制版目录。不要同时启用两个版本处理同一个账号。各扩展的设置与历史由 Chrome 分开保存，重新加载扩展不会自动开始投递。

## 0.2.6 的继续沟通与自动发送修复

- 增加“继续沟通”中间状态：点击立即沟通后，如果仍停在同一岗位详情页且没有聊天输入框，但按钮变为继续沟通，会接着点击一次继续沟通，等待当前任务的消息页。任务中的继续沟通动作只执行一次；页面重载保留该记录，不反复点击。
- 支持同一任务打开同岗位详情中间标签后继续执行，聊天页沿用原任务、话术和简历图片配置；处理结束清理该任务的临时标签，不动原职位列表。
- 修复发送按钮外层容器被误选：定位真实按钮或明确的发送控件，等待草稿和可用按钮连续就绪后自动点击。当前任务的文字已经在输入框时直接沿用；不会把别的草稿覆盖成自己的文字。
- 将“准备草稿”和“请求发送”分为两个阶段。草稿已填写但尚未点击发送，不登记已沟通；发送请求全局只允许一次，避免不同任务标签或页面重载重复发送。
- 点击发送后同时确认输入框清空与新增聊天记录，随后按原设置发送简历图片。日志新增继续沟通动作、草稿填写/沿用、真实发送控件和发送确认；不保存聊天正文。

## 之前的弹层识别范围更新

- 只有点击当前岗位的“立即沟通/继续沟通”后、等待真实聊天输入框时，才判断订阅弹层；扫描列表、识别职位、打开详情和点击沟通之前均不执行弹层关闭。
- 点击后若可见弹层同时包含“订阅”和“消息”（顺序不限），或弹层文字/元素明确指向二维码/扫码，只点击该弹层内部的关闭控件，不关闭职位窗口，也不在弹层里填写消息或图片。关闭后继续当前岗位的正常投递流程。
- 二维码只能按页面可见文字和 DOM 元素线索判断；无法从截图中通用识别没有任何标识的二维码。没有可确认的弹层内部关闭控件时，不盲点其他地方。

## 此前的兼容性更新

- 增加岗位详情、沟通页/输入框、文字发送确认和简历图片发送确认四组最长等待设置。页面提前就绪时立即继续，不会强制等待到上限。
- 准确识别含“订阅回复消息”的微信订阅弹层并只点击关闭。该弹层不是 BOSS 聊天输入框，插件不会在其中填写招呼语或粘贴图片；关闭后继续当前岗位，等待真正的聊天输入框并按原流程发送文字和简历图片。
- 输入框、发送按钮和图片入口均在实际发送前等待并再次核对，减少 Windows 页面尚未加载完成就判失败的情况。
- 左右岗位不一致、输入框未出现、临时投递页失败等岗位级问题会记录并跳过当前岗位，不再终止整轮。
- 若文字已取得明确发送证据、图片随后失败，保留文字防重记录并继续下一条，不重复发送文字。

## 通用化内容

以下页面字段都各自拥有“包含词”和“排除词”，并能选择“命中任意 1 个”“全部命中”或“至少命中 N 个不同词”：

| 字段 | 读取来源 | 典型用途 |
| --- | --- | --- |
| 岗位标题 | 职位名称 | 只保留行政专员/行政助理，排除实习 |
| 职位正文 | 职责与任职要求 | 要求出现会议安排或档案管理，排除长期驻外 |
| 岗位标签 | 页面技能/经验标签 | 单独按 Office、行政管理等标签筛选 |
| 公司名称 | 当前岗位卡片公司 | 公司白名单、黑名单、外包名单、大厂手动处理名单 |
| 工作地点 | 岗位地点文字 | 上海、杭州、某区等 |
| 招聘者姓名 | 招聘者显示名 | 只在有明确业务需要时使用 |
| 活跃标签 | 在线、刚刚活跃、3日内活跃等原始文字 | 按页面原始标签保留或排除 |
| 回复标签 | 今日回复、回复率高等原始文字 | 优先有回复信号的岗位 |

招聘者活跃时间另有一个 0–3650 天的数值上限：0 表示不限制，1 表示当天内，3 表示三天内。宽松范围包含严格范围，例如三天内包含在线、刚刚活跃、当天、一至三天内。页面没有可确认的活跃状态时，可以设置跳过或放行。

沟通次数也不再写死：可以设置同岗位最多沟通次数、第一次后的最短间隔、第二次及以后最短间隔、后续沟通是否必须跨北京时间自然日，以及同公司其他岗位防重时间。

完整填写示例见 [CONFIGURATION_EXAMPLES.md](CONFIGURATION_EXAMPLES.md)，配置与代码关系见 [DEVELOPER_NOTES.md](DEVELOPER_NOTES.md)。

## 筛选计算规则

- 所有空白组完全不参与判断。
- 已填写的多个“包含组”之间是“并且”：每一组都必须通过。
- 任一“排除组”达到自己的阈值，就跳过当前岗位。
- 一个词在页面中重复多次只计一次；重复填写也只计一次。
- 用换行、中文/英文逗号或中文/英文分号分隔词条。空格和顿号不会分隔词条。
- 中文按字面包含匹配；纯英文技术词按完整词匹配；公司、地点、招聘者、活跃和回复标签按片段匹配。
- 规则不做行业猜测。例如名称里有“科技”不会自动判定为大厂，正文提到客户名称也不会自动把该客户当成当前雇主。
- 字面规则不理解否定。排除“出差”也可能命中“不需要出差”，应避免过宽词条。

本地筛选发生在模型调用之前。不通过的岗位不请求模型，因此不会为明显跳过的岗位消耗模型调用。面板日志会记录字段、匹配方式、实际命中的词以及跳过原因。

## 打招呼方式

岗位页面板可选择：

1. **自定义模板**：不调用模型，可使用 `{称呼}`、`{招聘者}`、`{公司}`、`{岗位}`、`{城市}`、`{沟通次数}`。未知变量或所需字段缺失时不会带着占位符发送。
2. **AI 生成**：在设置页填写自己的个人总结、写作要求、模型名称、Base URL 和 API Key。当前支持智谱与 DeepSeek 的 OpenAI 兼容 Chat Completions 接口域名。

AI 只负责为已通过本地规则的岗位写话术，不增加隐藏的岗位排除条件。模型输入包含当前岗位信息、招聘者显示名、使用者填写的个人总结和写作要求；模板方式不会请求模型。

话术中的岗位名会使用“对话简称”，但筛选、身份核对、日志和防重仍保留完整原始岗位名。例如：

- `徐汇区漕河泾商圈/诚聘顾问（无需电销）` → `顾问`
- `高提成股票投资顾问＋员工宿舍` → `高提成股票投资顾问`
- `商务代表（上海办事处）` → `商务代表`
- `奢侈品销售` → 保持 `奢侈品销售`

这不是把所有符号后的文字一律删除：只有尾部括号说明、明确招聘前缀和明确福利尾巴会被清理；无法可靠判断时保留原意。

**一定不要泄漏你的 API Key！这是通用接口凭证，别人拿到你的 API Key 后可以直接使用。切记，切记！！！！！！** API Key 保存在当前 Chrome 扩展的本地存储中，但该存储不是加密密码保险箱。不要在公共或多人共用的 Chrome 配置中保存。分发目录和 ZIP 中不包含任何 Key。

## 发送节奏和防重

- Windows 会自动启用“前台临时标签兼容模式”：插件在独立岗位详情页完成沟通，结束后关闭临时页并返回原职位列表。这样不依赖 Windows Chrome 是否允许隐藏后台页弹出聊天窗口。
- 若沟通按钮本身提供可验证的 BOSS 站内聊天地址，插件会让现有临时标签页直接进入该地址，不再依赖弹出新页面。
- 若只能使用页面点击，日志会保存系统类型、按钮文字、任务标签和页面路径。按钮从“立即沟通”变成“继续沟通”但没有输入框时，先接着执行一次继续沟通；仍无法进入聊天时记录失败或待核对原因，并继续下一岗位。
- 新窗口或新标签聊天页不再强制要求与详情页处于同一窗口；只要来源标签或当前招聘者/公司/岗位文字能够核对，就可以接管。
- 每条成功后的随机等待、每批数量、每批额外等待、单轮上限和每日上限均可设置。
- 同岗位历史与同公司时间窗口用于防重复。昨日或更早记录只要仍在本地历史中，也会参与判断。
- 跳过和失败不占成功额度；明确成功才增加成功数。
- 单岗位读取失败、字段不一致、筛选不符、模型失败或临时投递页失败会记录并继续下一条。
- 只有验证码/账号限制、来源列表已离开、持久化状态失败等全局无法继续的情况才暂停整轮。
- 发送结果未知时不会自动重发该岗位，以避免重复消息。

页面加载等待设置均为上限：默认岗位详情 30 秒、沟通页/输入框 60 秒、文字发送确认 15 秒、简历图片发送确认 45 秒。可以在设置页按 Windows 电脑和网络情况调整。若页面提前就绪，流程会立即继续。

随机等待不能保证不会触发平台限制，也不是绕过风控的手段。实际平台限制始终优先。

## 简历图片

可在设置页选择一张 JPG、PNG 或 WebP 图片，最大 8 MB。图片副本只保存在当前扩展本地存储中，不写进分发目录，也不发送给模型。开启后会先确认真实聊天页和唯一图片入口，再发送文字和图片；若未找到图片入口，不会退化成只发送文字。文字已经取得明确发送证据而图片随后失败时，会保留文字防重记录并继续下一条。

订阅二维码弹层属于订阅提示，不是站内聊天编辑器。只有点击“立即沟通/继续沟通”后，插件才会在等待聊天输入框时按上述规则关闭明确的弹层，随后继续当前岗位；不会在识别职位时关闭，也不会仅因为出现该弹层而跳过岗位。仍建议按设置页提示关闭 BOSS 的自动默认打招呼。

## 消息页批量激活

消息激活与新岗位投递是两个互斥模块。它在消息页先扫描和预览联系人，再根据对方已读/未读、是否回复、我方是否发过消息等设置筛选。身份或状态无法确认、检测到拒绝信号、输入框已有草稿或发送结果不明时不会盲目发送。

## 日志

岗位面板的“运行日志 / 具体未发送原因”记录：岗位、公司、阶段、状态、当前字段、规则、命中词和错误。单岗位失败不会被伪装成“筛选不符”。日志不保存 API Key、简历图片或聊天正文，但可能包含招聘者姓名、公司和岗位，分享前请检查。

## 开发与本地验证

在本目录运行：

```bash
npm run check
npm test
```

这些命令只做 JavaScript 语法检查与虚构数据测试，不启动浏览器、不连接 BOSS、不调用真实模型、不发送消息。`tests/browser-execution-lock.mjs` 是浏览器执行锁，不能删除或绕过。

主要文件：

- `shared/config.js`：筛选字段定义、默认值、解析和配置校验。
- `shared/core.js`：字段筛选、HR 活跃解析、模板变量和沟通资格。
- `options.html` / `options.js`：设置页；筛选表单由字段定义动态生成。
- `settings.js`：无个人信息的默认设置。
- `content.js` / `background.js`：岗位读取、任务状态、发送和日志。
- `CONFIGURATION_EXAMPLES.md`：面向普通使用者的填写示例。
- `DEVELOPER_NOTES.md`：面向维护者的扩展说明与安全边界。
