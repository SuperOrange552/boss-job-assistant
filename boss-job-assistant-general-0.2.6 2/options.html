岗位筛选个人总结与AI要求字数与发送节奏简历与接口

01 · 可配置岗位筛选

包含组填写后必须通过，排除组触发后会跳过；所有空白组不参与判断。多个已填写的包含组之间是“并且”关系。每个字段都能单独选择任意命中、全部命中或至少命中 N 个。

规则只按当前页面可读取的文字判断，不猜测公司行业或岗位性质。筛选字段由代码中的统一定义自动生成，详细示例见包内 CONFIGURATION_EXAMPLES.md。

招聘者活跃时间上限（可选）

若想按页面原始标签筛选，也可使用上方“招聘者活跃标签”的包含/排除词；时间上限和标签词同时填写时，两者都要通过。

02 · 个人总结与 AI 写作要求

“打招呼”是主动联系招聘者的开场消息，不是自动回复聊天。AI / 自定义模板的选择，以及模板编辑、预览和保存，已移到 BOSS 岗位页面板；这里不再设置默认话术。

AI以当前岗位职责为主，结合少量个人经历生成开场话术；模板模式不调用模型。这些后台设置在新的一轮开始时读取，运行中不会改变。

03 · 字数、发送节奏与次数

以下均在后台配置。两组间隔为随机整数秒；达到每批数量时，每条间隔与每批额外休息相加，AI生成耗时另算。间隔不能保证不触发平台限制。

沟通次数、两段间隔和跨日要求全部可设置。修改设置不会删除原有沟通历史；历史仍用于防止重复发送。批量激活另有独立防重记录。

04 · 页面加载与发送确认等待

以下都是“最长等待上限”，不是每条固定停留时间。页面或控件提前就绪时会立即继续。网络较慢或 Windows 电脑可适当调大。

只有点击岗位的“立即沟通/继续沟通”之后，插件才检查订阅弹层。若弹层内同时出现“订阅”和“消息”（顺序不限），或明确出现二维码/扫码线索，只点击弹层内部的关闭按钮；职位识别、详情读取及点击沟通之前绝不关闭弹层或职位窗口。关闭后继续当前岗位，等待真实聊天输入框并正常发送文字与简历图片；不会在弹层内输入。没有明确内部关闭控件的弹层不会盲点。

消息批量激活设置（本次暂不调整）

05 · 消息页批量激活

独立入口，在 BOSS 消息页使用：先读取并预览联系人状态，勾选名单，再确认发送。不会去搜索岗位或重新投递简历。

“对方已读/未读”来自我方消息的阅读标识，不是左侧红色未读数量；“对方回复过”和“我方发过消息”分别判断。状态无法确认时显示未知，不据此猜测。拒绝或不再联系信号会跳过。

简历图片

选择一次 JPG、PNG 或 WebP 图片（最大 8 MB）。图片只保存在当前 Chrome 扩展的本地存储中，不会写进插件文件，也不会发送给智谱或 DeepSeek。

尚未保存简历图片

浏览器不能在以后自动读取一个普通本地路径，所以这里会保存你选择的图片副本。更换图片后需要重新保存。若文字已成功发送、但图片发送结果无法确认，插件会把文字记入防重记录，记录图片失败原因，然后继续下一个岗位；不会重复发送文字。

模型接口

可以填写 Base URL，也可以直接粘贴以 /chat/completions 结尾的完整接口地址；插件会自动规范化，避免重复拼接路径。

API Key 安全提醒：一定不要泄漏你的 API Key！这是通用接口凭证，别人拿到你的 API Key 后可以直接使用。切记，切记！！！！！！

API Key 会保存在 Chrome 的扩展本地存储中，不会显示在 BOSS 页面或扩展弹窗中；但该存储不是加密密码保险箱。不要在公共或多人共用的 Chrome 配置中保存。

单条发送与使用边界

批量操作另需在对应页面预览并确认开始。验证码、风险提示、身份不一致、发送状态不明确时停止；不绕过平台限制。请勿同时启用个人版和通用版处理同一账号。
